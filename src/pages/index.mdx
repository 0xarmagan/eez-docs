EEZ is a smart contract protocol that brings synchronous composability to Ethereum's rollup ecosystem. By pre-computing state transitions off-chain and verifying them on-chain through a configurable multi-prover system, EEZ lets contracts on different rollups call each other atomically — all settled within a single L1 block. Whether you're building cross-rollup flash loans, unified liquidity layers, or atomic DeFi primitives that span chains, EEZ gives you the execution model to make it possible.

:::warning
EEZ is an early-stage, unaudited implementation. Interfaces, storage layout, and execution semantics are still evolving. Do not use this for value-bearing deployments.
:::

## How onboarding works

The following steps summarise the path from zero to a live cross-rollup call. Each step links to a dedicated guide for deeper detail.

## Step 1 — Deploy your rollup manager

Deploy a `Rollup.sol`-conforming manager contract on L1. This contract holds your proof system addresses, verification keys, and the M-of-N threshold that controls which proofs are accepted for your rollup.

## Step 2 — Register with the EEZ registry

Call `EEZ.registerRollup(rollupContract, initialState)` on L1. The registry assigns a unique rollup ID (starting at 1) and fires the `rollupContractRegistered` callback on your manager so it learns its ID.

## Step 3 — Deploy EEZL2 on your rollup

Deploy the `EEZL2` contract on your L2 with your rollup ID and a trusted system address. The system address is the only account permitted to load execution tables and drive incoming cross-chain calls — in production this is a key held exclusively by the rollup's sequencer node.

## Step 4 — Create CrossChain proxies

For each L2 address that will receive cross-chain calls, call `createCrossChainProxy(originalAddress, rollupId)` on the L1 EEZ contract. Proxies are deterministic CREATE2 addresses that act as the cross-chain identity for each `(address, rollupId)` pair.

## Step 5 — Post and verify a batch

Your off-chain node pre-computes state transitions and packages them into a `ProofSystemBatchPerVerificationEntries` struct. Call `postAndVerifyBatch` on L1. Proofs from every required proof system are verified atomically — one failure reverts the entire batch.

## Step 6 — Execute the cross-chain call

In the same L1 block, trigger the cross-chain call through the proxy. The proxy routes to `EEZ.executeCrossChainCall`, which consumes the matching execution entry from the queue and returns the pre-committed return data.
