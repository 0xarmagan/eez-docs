**A contract on one rollup calls a contract on another and gets the return value in the same L1 block** — atomic cross-rollup composability, verified on-chain. No lock-and-mint bridges, oracles, or relayers in the path.

:::caution
Early-stage and **currently in internal and external audit** — interfaces and storage layout are still in flux. Not for production use.
:::

## What is EEZ

Ethereum's rollups each hold their own state. A contract on one cannot call a contract
on another, so anything cross-chain today goes through a bridge: send a message, wait
for it to arrive, handle the callback. One logical operation becomes two transactions
with a gap in the middle.

EEZ closes the gap. A cross-rollup call is an ordinary Ethereum `CALL` to a local
address that stands in for the remote contract:

```solidity
// `counterProxy` stands in for a Counter contract on another rollup.
uint256 value = ICounter(counterProxy).increment();
```

That works because the outcome is computed **before** the call runs. An off-chain
prover works out what the call will do — which contracts run, what they return, how
state changes — and posts it to L1 as a proved record. When the transaction executes,
the protocol doesn't fetch anything from another chain: it replays the recorded calls
and checks that reality matches the record. If it matches, the return value comes
back in the same block. If anything differs, the whole call reverts.

So, precisely: **EEZ does not move messages between chains — it verifies pre-computed
outcomes.** That is why there is no bridge in the path and nothing to wait for. It
relies on the rollups involved being [based rollups](/spec/core-protocol/) that share
Ethereum's L1 sequencer, so their blocks are built together rather than independently.

EEZ is not a bridge (nothing is locked, minted, or wrapped), not a messaging layer
(no inbox to poll, no callback to handle), and not a rollup — it is a protocol that
existing rollups adopt.

The [specification](/spec/core-protocol/) covers the rest: the data model, the
protocol functions, how outcomes are hashed and verified, and the invariants the
protocol enforces.
