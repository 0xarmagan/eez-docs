`EEZL2` is the L2-side manager for EEZ synchronous cross-chain composability. It receives execution tables from a privileged [`SYSTEM_ADDRESS`](/reference/glossary#system-address), then fulfills cross-chain calls as individual transactions arrive from registered proxy contracts within the same block. The L2 contract has no per-rollup state deltas, no queue interleaving, and no on-chain ZK verification — just a single flat execution table (`entries`) loaded once per block and consumed sequentially by proxy-gated calls. Read-only (STATICCALL) cross-chain calls resolve separately from that table: a top-level read matches against the same-block `staticEntries` pool, and a reentrant read matches a STATIC-kind row inside the active entry's own unified `expectedOutgoingCalls` table — there is no standalone lookup struct.

:::note
**L2 trust assumption.** L2-side delivery does not carry its own ZK proof. Instead, it rests on `SYSTEM_ADDRESS` being controlled by the honest sequencer or node operator: only that address can call `loadExecutionTable` or `executeIncomingCrossChainCall`, and the L2 execution it installs is expected to be the exact table already committed to on L1 (via the batch proof verified by `EEZ.postAndVerifyBatch`). This is a deliberate design choice — L2 correctness is anchored in the L1 proof plus the sequencer's honest publication of the matching L2 table, rather than in a separate L2-side proof. Rollups that want a stronger guarantee must add their own L2-level verification on top.
:::

## Public State

| Variable | Type | Description |
| --- | --- | --- |
| `ROLLUP_ID` | `uint64` (immutable) | The rollup ID assigned to this L2. Must be non-zero — zero is reserved for mainnet (L1) in all cross-chain call hash computations. |
| `SYSTEM_ADDRESS` | `address` (immutable) | The privileged address permitted to load and replace execution tables. Node-controlled; never adversarial. |
| `USE_GAS_LEFT` | `bool` (immutable) | Whether the `callGas` folded into *outgoing* cross-chain call hashes (calls leaving this L2 via `executeCrossChainCall`) is the `gasleft()` observed at manager entry. When `false`, `callGas` is fixed at `0` and outgoing hashes are gas-independent, pre-computable without observing forwarded gas. `true` is the intended production mode once the node supplies observed gas. |
| `entries` | `ExecutionEntry[]` (public) | The array of pre-computed execution entries currently loaded, consumed sequentially via `executeCrossChainCall`. Replaced wholesale by `loadExecutionTable` or `executeIncomingCrossChainCall`. Renamed from `executions`. |
| `staticEntries` | `StaticExecutionEntry[]` (public) | The array of pre-computed top-level static (read-only) entries currently loaded, resolved via `staticCrossChainCall` outside any active execution. Replaced wholesale alongside `entries`, and — unlike L1's pinned static pool — only resolvable in the exact block they were loaded (`lastLoadBlock == block.number`; L2 has no state-root pins, so the block gate is what bounds staleness). Renamed from `lookupCalls`. |
| `lastLoadBlock` | `uint256` (public) | The block number of the most recent `loadExecutionTable` or `executeIncomingCrossChainCall` call. Entries and static entries can only be consumed in this same block. |
| `entryIndex` | `uint256` (public) | The cursor into the `entries` array pointing to the next entry to be consumed. Advances by one per successful top-level `executeCrossChainCall`. Renamed from `executionIndex`. |
| `authorizedProxies` | `mapping(address => ProxyInfo)` (public, inherited from `EEZBase`) | Maps a deployed `CrossChainProxy` address to the `ProxyInfo { isProxy, originalAddress, originalRollupId }` it represents. `isProxy` is an explicit registration flag (rather than inferring registration from a zero `originalAddress`). Populated by `createCrossChainProxy`, and also auto-populated inline by `_processNCalls` — which calls the same internal `_createCrossChainProxyInternal` deploy helper to register an unregistered source proxy on the fly during call dispatch, without going through the external entry point — and checked by `executeCrossChainCall`/`staticCrossChainCall`. Both `createCrossChainProxy`'s parameter and the stored `originalRollupId` are `uint64`, so there is no cross-width truncation on registration. |

## Trust Model

`SYSTEM_ADDRESS` is the sole entity permitted to write to the execution table. Because it is node-controlled and never reachable through proxy call paths, the protocol treats its table loads as authoritative. The block-gating rule enforces temporal freshness: `lastLoadBlock` must equal `block.number` when any entry is consumed, so a stale table from a prior block is simply never read — the next load overwrites it. A same-block re-load via `loadExecutionTable` or `executeIncomingCrossChainCall` replaces both `entries` and `staticEntries` atomically, resetting `entryIndex` to zero. This means a second load in the same block discards any unconsumed entries or static entries from the first load without error.

The `SYSTEM_ADDRESS` is never the target of reentrant cross-chain calls: `executeIncomingCrossChainCall` is only callable from `SYSTEM_ADDRESS` itself and is not reachable from inside an active execution. This guarantees that no attacker can wipe or swap the table mid-execution by exploiting reentrancy.

## Constructor

Deploys the `EEZL2` contract with a fixed rollup ID, system address, and outgoing-call gas-keying mode. All three values are stored as immutables and cannot be changed after deployment.

```solidity
constructor(uint64 _rollupId, address _systemAddress, bool _useGasLeft)
```

#### Parameters

| Name | Type | Description |
| --- | --- | --- |
| `_rollupId` | `uint64` | The rollup ID for this L2. Must be non-zero — the value `0` is the mainnet sentinel used in cross-chain call hashes to denote L1 as the source or destination, and is rejected with `InvalidRollupId`. |
| `_systemAddress` | `address` | The privileged address authorized to call `loadExecutionTable` and `executeIncomingCrossChainCall`. Typically a node-controlled account with no human-accessible private key. |
| `_useGasLeft` | `bool` | Whether outgoing cross-chain call hashes (calls leaving this L2 via `executeCrossChainCall`) fold the observed `gasleft()` at manager entry (`true`), or a fixed `0` (`false` — gas-independent keying). Stored as `USE_GAS_LEFT`. |

<summary>RECOVERY_ADDRESS — Recipient of ether swept from undeployed proxies</summary>

Returns the address that receives ether recovered on this manager's behalf. `CrossChainProxy`'s constructor best-effort-sweeps any ether sent to its own address before deployment (otherwise permanently stuck) to `IEEZ(_eez).RECOVERY_ADDRESS()`; a failed transfer never blocks proxy creation. `RECOVERY_ADDRESS` is declared once on the shared `IEEZ` interface — on L1's `EEZ` it is a distinct constructor-set immutable, but on `EEZL2` it always returns `SYSTEM_ADDRESS`, the same address `executeCrossChainCall` forwards inbound `msg.value` to when it burns ether on this L2.

**Who can call it:** Anyone.

```solidity
function RECOVERY_ADDRESS() external view returns (address)
```

#### Returns

| Name | Type | Description |
| --- | --- | --- |
| (return) | `address` | `SYSTEM_ADDRESS`. |

<details>
<summary>loadExecutionTable — Replace the execution table for the current block</summary>

Replaces the entire execution table with a fresh set of entries and static entries. After the call, `entryIndex` is reset to `0` and `lastLoadBlock` is set to the current block number. Any entries or static entries remaining from a previous load are discarded without error.

You call this function when the node has pre-computed execution entries for the current block and wants to make them available for consumption. The entries must be consumed in the same block — after the block advances, `lastLoadBlock != block.number` and all consumption attempts revert with `ExecutionNotInCurrentBlock`.

**Who can call it:** Only `SYSTEM_ADDRESS`.

**Emits:** `ExecutionTableLoaded(_entries)`

```solidity
function loadExecutionTable(
    ExecutionEntry[] calldata _entries,
    StaticExecutionEntry[] calldata _staticEntries
) external onlySystemAddress
```

#### Parameters

| Name | Type | Description |
| --- | --- | --- |
| `_entries` | `ExecutionEntry[]` | The full list of pre-computed execution entries to load. Each entry carries an inbound `proxyEntryHash`, its own flat call array (`incomingCalls`), a unified reentrant call table (`expectedOutgoingCalls`) that also serves nested static/reverted reads, an expected `rollingHash`, a `success` flag, and pre-computed `returnData` — there is no separate `expectedLookups` field. Entries are consumed in order via `executeCrossChainCall`. See the [Data Types](/contracts/data-types) reference for the full `ExecutionEntry` structure. |
| `_staticEntries` | `StaticExecutionEntry[]` | Top-level static (read-only) entries available for resolution via `staticCrossChainCall`, matched by `proxyEntryHash` alone and only resolvable in the same block they were loaded. Pass an empty array when no top-level static reads are needed. |

#### Errors

| Error | Condition |
| --- | --- |
| `Unauthorized` | Caller is not `SYSTEM_ADDRESS`. |

</details>

<details>
<summary>executeIncomingCrossChainCall — Load a table and drive the first entry inline</summary>

Atomically loads a new execution table and drives the first entry through the flat call processor. This is the system-initiated delivery path for inbound cross-chain calls arriving from another rollup (including L1).

The function enforces strict equality between `msg.value` and the declared `value` parameter — the node mints exactly the right amount of ETH on L2 to forward to the destination. The first entry in `_entries` must have a `proxyEntryHash` that matches `computeCrossChainCallHash(false, sourceAddress, sourceRollup, destination, ROLLUP_ID, value, 0, data)`, or the call reverts with `EntryHashMismatch`. After `_entries[0]` is fully executed, `entryIndex` is advanced to `1` so that subsequent `executeCrossChainCall` invocations in the same transaction can consume `entries[1]`, `entries[2]`, and so on without re-consuming `entries[0]`.

**Who can call it:** Only `SYSTEM_ADDRESS`.

**Emits:** `ExecutionTableLoaded(_entries)`, `IncomingCrossChainCallExecuted(crossChainCallHash, destination, value, data, sourceAddress, sourceRollup)`, `ExecutionConsumed(crossChainCallHash, 0)`, then — as `_entries[0].incomingCalls` are processed — `CrossChainProxyCreated(proxy, originalAddress, originalRollupId)` (only if `_processNCalls` auto-registers an unregistered source proxy inline via `_createCrossChainProxyInternal`), `CallResult(0, callNumber, success, returnData)` (per call), `CallsReverted(0, startCallNumber, nCalls)` (per force-revert span), and finally `EntryExecuted(0, rollingHash, callsProcessed, outgoingCallsConsumed)` — emitted last, after the rolling-hash check passes.

```solidity
function executeIncomingCrossChainCall(
    address destination,
    uint256 value,
    bytes calldata data,
    address sourceAddress,
    uint64 sourceRollup,
    ExecutionEntry[] calldata _entries,
    StaticExecutionEntry[] calldata _staticEntries
) external payable onlySystemAddress returns (bytes memory result)
```

#### Parameters

| Name | Type | Description |
| --- | --- | --- |
| `destination` | `address` | The contract address on this L2 that the inbound call targets. |
| `value` | `uint256` | The ETH value (in wei) attached to the inbound call. Must equal `msg.value` exactly; any discrepancy reverts with `ValueMismatch`. |
| `data` | `bytes` | The calldata for the destination contract — the selector and ABI-encoded arguments. |
| `sourceAddress` | `address` | The original caller identity on the source rollup. Used together with `sourceRollup` to derive the source proxy address on this L2. |
| `sourceRollup` | `uint64` | The rollup ID of the chain where the call originated. Pass `0` for a call originating from L1 (mainnet). |
| `_entries` | `ExecutionEntry[]` | The execution entries to load. Must be non-empty; `_entries[0]` is consumed by this call. Any remaining entries become available for proxy-driven consumption via `executeCrossChainCall`. |
| `_staticEntries` | `StaticExecutionEntry[]` | Top-level static entries to load alongside the entries, for STATICCALL reads. Pass an empty array when none are needed. |

#### Returns

| Name | Type | Description |
| --- | --- | --- |
| `result` | `bytes` | The pre-computed return data from `_entries[0]`, as declared in `entry.returnData`. This is the value the source chain's prover committed to as the return value for the inbound call. |

#### Errors

| Error | Condition |
| --- | --- |
| `Unauthorized` | Caller is not `SYSTEM_ADDRESS`. |
| `EmptyEntries` | `_entries.length == 0`. |
| `ValueMismatch` | `msg.value != value`. |
| `EntryHashMismatch` | `_entries[0].proxyEntryHash` does not match the computed call hash. |
| `StaticCallWithValue` | A call marked `isStatic` in `_entries[0]`'s call table was loaded with a non-zero `value`. |
| `RevertSpanOutOfBounds(uint256 start, uint256 span, uint256 length)` | A call's `revertNextNCalls` span extends past the end of the call array (malformed entry). |
| `RollingHashMismatch` | The rolling hash computed during execution does not match `_entries[0].rollingHash`. |

</details>

<details>
<summary>executeCrossChainCall — Execute a queued cross-chain call via proxy</summary>

Consumes the next execution entry and drives its flat call array through the processor.

When called outside an active execution (`_insideExecution() == false`), the function forward-scans `entries` from `entryIndex` for the first entry whose `proxyEntryHash` matches the computed call hash, advances `entryIndex` past it, sets up fresh transient state, and drives the full entry. When called during an active execution — meaning a destination contract called back into the manager via a proxy — the function routes to `_consumeNestedCall` instead, consuming the next matching row from the active entry's unified `expectedOutgoingCalls` table, without advancing `entryIndex`.

Any ETH attached to the call (`msg.value > 0`) is immediately forwarded to `SYSTEM_ADDRESS`. This is the L2 ETH burn: the protocol does not retain ETH on the L2 manager contract.

The computed call hash folds `callGas` as its own key field: the gas observed at manager entry (`uint64(gasleft())`) when `USE_GAS_LEFT` is `true`, else a fixed `0`.

**Who can call it:** Registered proxy contracts only — the caller's address is looked up in the `authorizedProxies` registry; an unregistered address reverts with `UnauthorizedProxy`.

The documented Emits and Returns below differ depending on which branch handles the call:

**Top-level call** (`_insideExecution() == false` — the common case, driven by `_consumeAndExecute`):

- **Emits:** `CrossChainCallExecuted(crossChainCallHash, msg.sender, sourceAddress, callData, msg.value, callGas)`, `ExecutionConsumed(crossChainCallHash, entryIndex)`, then — as the entry's `incomingCalls` are processed — `CrossChainProxyCreated(proxy, originalAddress, originalRollupId)` (only if `_processNCalls` auto-registers an unregistered source proxy inline), `CallResult(entryIndex, callNumber, success, returnData)` (per call), `CallsReverted(entryIndex, startCallNumber, nCalls)` (per force-revert span), and finally `EntryExecuted(entryIndex, rollingHash, callsProcessed, outgoingCallsConsumed)` — emitted last, after the rolling-hash check passes.
- **Returns:** `entry.returnData` — the pre-computed return data from the matched execution entry.

**Nested (reentrant) call** (`_insideExecution() == true` — the destination contract called back in via a proxy, so the call routes to `_consumeNestedCall` instead):

- **Emits:** `CrossChainCallExecuted(...)` (always emitted before the branch dispatch), then whatever `_processNCalls` emits as the matched row's own `incomingCalls` sub-array runs — `CrossChainProxyCreated(...)` (conditional), `CallResult(...)` (per call), `CallsReverted(...)` (per force-revert span). **`ExecutionConsumed` and `EntryExecuted` are never emitted on this path** — a nested call is a reentrant sub-action of an already-in-progress entry, not a new top-level consumption.
- **Returns:** the matched row's own `returnData` — **not** `entry.returnData`.

```solidity
function executeCrossChainCall(
    address sourceAddress,
    bytes calldata callData
) external payable returns (bytes memory result)
```

#### Parameters

| Name | Type | Description |
| --- | --- | --- |
| `sourceAddress` | `address` | The original caller address as seen by the proxy — the `msg.sender` of the call that entered the proxy's fallback. Used together with the proxy's registered `originalRollupId` to compute the cross-chain call hash. |
| `callData` | `bytes` | The original calldata forwarded by the proxy — the full `msg.data` that arrived at the proxy's fallback. |

See **Returns** in the branch breakdown above — the value differs between the top-level and nested paths.

#### Errors

| Error | Condition |
| --- | --- |
| `UnauthorizedProxy` | Caller is not a registered proxy. |
| `ExecutionNotInCurrentBlock` | `lastLoadBlock != block.number`. |
| `EtherTransferFailed` | The ETH forwarding to `SYSTEM_ADDRESS` failed. |
| `EntryNotFound(bytes32 crossChainCallHash, uint64 callGas)` | Top-level only: no entry from `entryIndex` onward has a matching `proxyEntryHash`. Carries the computed hash and the observed `callGas` so the entry-builder can reproduce the key. |
| `RollingHashMismatch` | Post-execution hash check failed. This is also how an unmatched *nested* call surfaces: a reentrant no-match folds a `CALL_NOT_FOUND` tag into the rolling hash and returns empty data instead of reverting immediately, so the divergence is only caught here, at the host entry's boundary check. |
| `StaticCallWithValue` | A call marked `isStatic` in the entry's call table was loaded with a non-zero `value`. |
| `RevertSpanOutOfBounds(uint256 start, uint256 span, uint256 length)` | A call's `revertNextNCalls` span extends past the end of the call array (malformed entry). |

</details>

<details>
<summary>executeInContextAndRevert — Self-call sandbox behind a force-revert span</summary>

Runs a slice of `CrossChainCall`s in an isolated context, then unconditionally reverts, carrying the resulting rolling-hash state out via the `ContextResult` error. This is the self-call mechanism `_processNCalls` uses to implement a force-revert span (a call flagged with a non-zero `revertNextNCalls`): it copies the `revertNextNCalls` consecutive calls (that triggering call included) into a fresh `memory` array, zeroes the copy's own span marker so the isolated re-run can't recurse into the same span, and invokes `this.executeInContextAndRevert(revertedSpan)` through a low-level `try`/`catch` — so every state change and event made while running the span (`CallResult`, any nested `CallsReverted`, any reentrant-table consumption) is rolled back by the EVM. The `catch` branch decodes `ContextResult` to recover `_rollingHash` and `_lastOutgoingCallConsumed`, and the caller then emits a single `CallsReverted` for the whole span.

Unlike L1's equivalent (which takes a plain call count into a shared, cursor-tracked flat-call array), `EEZL2` passes the actual `CrossChainCall[]` slice by `memory` — L2 has no global flat-call cursor to index into across the external self-call boundary, so the span's calls travel with the call itself.

Because the revert unwinds all state written inside the span, calling this function directly from outside `_processNCalls` cannot have any observable effect other than reverting — it exists purely as a self-call boundary.

**Who can call it:** Only this contract itself. `_processNCalls` invokes it via `this.executeInContextAndRevert(...)`; any other caller reverts with `NotSelf`.

**Emits:** None persist — this call always reverts, so any events emitted internally by `_processNCalls` during the span are rolled back with it. The caller separately emits `CallsReverted` after catching the revert.

```solidity
function executeInContextAndRevert(CrossChainCall[] memory calls) external
```

#### Parameters

| Name | Type | Description |
| --- | --- | --- |
| `calls` | `CrossChainCall[]` | The force-revert span's own calls, sliced into a fresh memory array by the caller before the self-call. |

#### Errors

| Error | Condition |
| --- | --- |
| `NotSelf` | Caller is not this contract itself (`msg.sender != address(this)`). |
| `ContextResult(bytes32 rollingHash, uint256 reentrantConsumed, uint256 callsProcessed)` | Always thrown on completion of the span (not truly an error — it's the transport carrying the post-span rolling hash and reentrant cursor back to the catching caller). `EEZL2` always sets `callsProcessed` (the third field) to `0` — that field exists only because `ContextResult` is shared with L1's flat-call cursor, which L2 doesn't have. |

</details>

<details>
<summary>staticCrossChainCall — Resolve a static cross-chain read</summary>

Resolves a pre-computed result for a read-only (STATICCALL) cross-chain call. The proxy's fallback automatically routes to `staticCrossChainCall` instead of `executeCrossChainCall` when it detects it is operating inside a STATICCALL frame (via its `staticCheck` self-call mechanism).

Inside an active execution, the function scans the active entry's unified `expectedOutgoingCalls` array — forward from `_lastOutgoingCallConsumed`, *without* advancing it, since a `view` frame cannot mutate the cursor — for a row whose `expectedOutgoingHash` matches `keccak256(crossChainCallHash, _rollingHash)`. Outside an active execution, it scans the persistent `staticEntries` pool, gated on `lastLoadBlock == block.number` (L2 has no state-root pins, so the same-block gate is what bounds staleness), matching by `proxyEntryHash` alone.

In both cases, on a match the shared resolver re-runs the matched row's own sub-calls via STATICCALL, verifies their untagged rolling hash against the row's stored hash, then returns `returnData` if the row's `success` flag is `true`, or reverts with `returnData` if `false` — letting the caller's `try`/`catch` observe a pre-computed revert. On no match, the function reverts immediately with `ExecutionNotFound` — unlike a reentrant CALL no-match, a `view` frame can't fold a `CALL_NOT_FOUND` tag to defer the failure to a later rolling-hash check.

**Who can call it:** Registered proxy contracts only.

```solidity
function staticCrossChainCall(
    address sourceAddress,
    bytes calldata callData
) external view returns (bytes memory)
```

#### Parameters

| Name | Type | Description |
| --- | --- | --- |
| `sourceAddress` | `address` | The original caller address, as forwarded by the proxy's fallback. |
| `callData` | `bytes` | The original calldata, as forwarded by the proxy's fallback. |

#### Returns

| Name | Type | Description |
| --- | --- | --- |
| (return) | `bytes` | The pre-computed return data for the matched row or static entry. If it is marked `!success`, this function reverts with that data instead of returning it. |

#### Errors

| Error | Condition |
| --- | --- |
| `UnauthorizedProxy` | Caller is not a registered proxy. |
| `ExecutionNotInCurrentBlock` | Top-level path only: `lastLoadBlock != block.number`. |
| `ExecutionNotFound` | No matching row was found in the active entry's `expectedOutgoingCalls` (reentrant), or no matching entry was found in `staticEntries` (top-level). |
| `StaticCallProxyNotDeployed(address sourceProxy)` | A sub-call in the matched row's own calls targets a source proxy address with no deployed code — a `STATICCALL` to a codeless address would silently succeed as a no-op, so this is rejected instead. |
| `NonStaticSubCall` | A sub-call in the matched row's own calls is not flagged `isStatic` — dispatch is read-only regardless of the flag, so a mismatch is rejected rather than silently letting a proven state-changing call run read-only. |
| `StaticCallWithValue` | A sub-call flagged `isStatic` carries a non-zero `value`. |
| `RollingHashMismatch` | The sub-call rolling hash does not match the row's stored hash. |

</details>

<details>
<summary>computeCrossChainCallHash — Compute the binding hash for a cross-chain call (inherited from EEZBase)</summary>

Computes the `crossChainCallHash` that binds a cross-chain call's parameters together — the same hash checked against `proxyEntryHash` / `ExpectedOutgoingCrossChainCall.expectedOutgoingHash` throughout execution, and against `_entries[0].proxyEntryHash` in `executeIncomingCrossChainCall`. A pure function of its inputs: identical parameters always produce the same hash, regardless of chain state. The formula is shared byte-for-byte with L1's `EEZ`, so off-chain tooling, provers, and both chains' contracts all derive the same value from the same eight fields.

**Who can call it:** Anyone (`pure`, no state read).

```solidity
function computeCrossChainCallHash(
    bool isStatic,
    address sourceAddress,
    uint64 sourceRollupId,
    address targetAddress,
    uint64 targetRollupId,
    uint256 value,
    uint64 callGas,
    bytes memory data
) public pure returns (bytes32)
```

#### Parameters

| Name | Type | Description |
| --- | --- | --- |
| `isStatic` | `bool` | Whether this is a read-only (STATICCALL) key. A static call and an otherwise-identical state-changing call hash to different values. |
| `sourceAddress` | `address` | The original caller identity on the source chain. |
| `sourceRollupId` | `uint64` | The rollup ID of the chain where the call originated. `0` denotes L1 (mainnet). |
| `targetAddress` | `address` | The destination contract address. |
| `targetRollupId` | `uint64` | The rollup ID of the call's destination. `0` denotes L1 (mainnet). |
| `value` | `uint256` | The ETH value (in wei) attached to the call. Always `0` for a static key. |
| `callGas` | `uint64` | Gas-keying field. `0` at every call site except an outgoing call leaving an L2 with `USE_GAS_LEFT == true`, where it is the `gasleft()` observed at manager entry. Always `0` for a static key — a read never keys on gas. |
| `data` | `bytes` | The calldata for the destination contract. |

#### Returns

| Name | Type | Description |
| --- | --- | --- |
| (return) | `bytes32` | `keccak256(abi.encode(isStatic, sourceAddress, sourceRollupId, targetAddress, targetRollupId, value, callGas, data))` — the cross-chain call hash. |

</details>
