EEZ uses two parallel families of execution structs: one for L1 (`IEEZ.sol`) and one for L2 (`IEEZL2.sol`). The L1 family uses absolute directional names (`L2ToL1Call`, `ExpectedL1ToL2Call`) because L1 always knows which direction a call moves. The L2 family uses self-relative names (`CrossChainCall` / `incomingCalls`, `ExpectedOutgoingCrossChainCall` / `expectedOutgoingCalls`) because an L2's cross-chain counterparty may be L1 or another L2 — absolute names would be wrong in the latter case. The L2 structs are intentionally leaner: they omit `StateUpdate`, `destinationRollupId`, and `ExpectedStateRootPerRollup`, which are meaningful only in the context of L1's multi-rollup registry.

Reentrant reads and reverting reentrant calls are not separate structs — they're ordinary rows of the same unified reentrant table (`ExpectedL1ToL2Call` on L1, `ExpectedOutgoingCrossChainCall` on L2), distinguished only by their content-addressed key and a `success` flag. Top-level static (read-only) calls resolve through a dedicated `StaticExecutionEntry`, the counterpart to `ExecutionEntry` for state-changing top-level calls.

## L1 Types (`IEEZ.sol`)

### `StateUpdate`

Describes one rollup's state transition caused by executing one entry. The `currentState` field is checked on-chain at consumption time against `rollups[rollupId].stateRoot`; a mismatch reverts `StateRootMismatch`. This makes entries content-addressed against the trajectory the proof committed to, preventing a stale or reordered entry from silently applying to the wrong chain state.

```solidity
struct StateUpdate {
    uint64  rollupId;
    bytes32 currentState;
    bytes32 newState;
    int256  etherDelta;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `rollupId` | `uint64` | The rollup whose state transitions. Must be a registered rollup ID in the EEZ registry. |
| `currentState` | `bytes32` | The expected state root of `rollupId` immediately before this entry is applied. Checked at consumption time against `rollups[rollupId].stateRoot`; reverts `StateRootMismatch` on mismatch. |
| `newState` | `bytes32` | The state root to write into `rollups[rollupId].stateRoot` after the entry is applied. |
| `etherDelta` | `int256` | Signed change in the rollup's ETH balance held by the registry. Positive means the rollup gains ETH (deposit or bridged-in); negative means it loses ETH (withdrawal or bridged-out). The registry enforces `InsufficientRollupBalance` on negative deltas that would underflow. |

### `L2ToL1Call`

A single call in an L1 execution entry's flat call array (`l2ToL1Calls[]`), or in a reentrant/static frame's own sub-array. On L2, the structurally identical type is named `CrossChainCall`.

```solidity
struct L2ToL1Call {
    uint16  revertNextNCalls;
    bool    isStatic;
    uint64  gas;
    address sourceAddress;
    uint64  sourceRollupId;
    address targetAddress;
    uint256 value;
    bytes   data;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `revertNextNCalls` | `uint16` | When non-zero, force-reverts this call and the next `revertNextNCalls - 1` calls (this one included). The calls execute (and may succeed), but all EVM state changes are rolled back. The rolling hash still records the calls' real outcomes. Use this when the source chain's prover marks a sequence as reverted even though the destination calls themselves succeed. `0` means no forced revert. |
| `isStatic` | `bool` | When `true`, the call is dispatched via STATICCALL — read-only, carries no ETH, and reverts on any state write. A static call with a non-zero `value` field is rejected with `StaticCallWithValue`. |
| `gas` | `uint64` | Gas limit for the target call. `0` means forward all remaining gas. |
| `sourceAddress` | `address` | The identity of the caller on the source rollup. Together with `sourceRollupId`, this is used to derive (or auto-create) the `CrossChainProxy` through which the call is forwarded. |
| `sourceRollupId` | `uint64` | The rollup ID of the chain where the call originated. Pass `0` for calls originating from L1 (mainnet) itself. |
| `targetAddress` | `address` | The contract to call on the destination rollup (L1 in this context). |
| `value` | `uint256` | ETH to forward with the call, in wei. Only accrues toward the entry's ether accounting when the call succeeds. Must be zero for static calls. |
| `data` | `bytes` | The calldata — ABI-encoded function selector and arguments. |

### `ExpectedL1ToL2Call`

One row of the unified reentrant table for a cross-chain call fired mid-execution back from L1 to an L2. A single table serves three kinds — plain **SUCCESS**, read-only **STATIC**, and try/catch'd **REVERTED** (`success == false`) — each content-addressed by one key: `expectedL1toL2Hash == keccak256(crossChainCallHash, expectedRollingHash)`. `crossChainCallHash` folds `isStatic` (a static read keys distinctly from a state-changing call), so STATIC and CALL kinds can never match each other's rows. Consumed by forward-scanning from the entry's `_lastL1ToL2CallConsumed` cursor. On L2, the structurally identical type is named `ExpectedOutgoingCrossChainCall`.

```solidity
struct ExpectedL1ToL2Call {
    bytes32      expectedL1toL2Hash;
    L2ToL1Call[] l2ToL1Calls;
    bytes32      revertedOrStaticRollingHash;
    bool         success;
    bytes        returnData;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `expectedL1toL2Hash` | `bytes32` | The position key: `keccak256(crossChainCallHash, expectedRollingHash)`, where `expectedRollingHash` is the live `_rollingHash` at the instant the reentrant call fires. This uniquely pins the execution point — no separate cursor coordinates or context index are needed. |
| `l2ToL1Calls` | `L2ToL1Call[]` | This frame's own sub-calls, run to completion. Every kind (SUCCESS, STATIC, REVERTED) carries its own array — there is no shared partition or `callCount` split with the parent entry. |
| `revertedOrStaticRollingHash` | `bytes32` | The expected rolling hash of the frame's sub-calls. Checked only for STATIC and REVERTED kinds (a plain SUCCESS row folds its sub-calls into the host's continuous hash instead). An empty `l2ToL1Calls[]` must carry a hash of `bytes32(0)`. |
| `success` | `bool` | Whether the reentrant call returns (`true`) or reverts (`false`) with `returnData`. For a STATIC-kind row, `success` governs whether the read returns normally or reverts with its payload. |
| `returnData` | `bytes` | The pre-computed return value delivered back to the caller, or the revert payload when `success == false`. |

### `ExecutionEntry` (L1)

The central TOP-LEVEL execution unit on L1. Each entry carries one or more rollups' state transitions plus a flat list of calls to execute and the unified reentrant-call table. When `success` is `true`, the top-level call returns `returnData`; when `false`, the entry runs, verifies, then reverts with `returnData` so all state effects roll back (the caller may `try`/`catch`). Loaded by `postAndVerifyBatch` and routed into per-rollup queues.

```solidity
struct ExecutionEntry {
    StateUpdate[]        stateUpdates;
    bytes32              proxyEntryHash;
    L2ToL1Call[]         l2ToL1Calls;
    ExpectedL1ToL2Call[] expectedL1ToL2Calls;
    bytes32              rollingHash;
    uint64               destinationRollupId;
    bool                 success;
    bytes                returnData;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `stateUpdates` | `StateUpdate[]` | Per-rollup state updates — the entry's full state transition. At least one update must be present (the prover asserts this — enforced on-chain). Each update's `currentState` is checked against the live registry state at consumption time. |
| `proxyEntryHash` | `bytes32` | The inbound proxy-entry call hash (`crossChainCallHash`) that triggers this entry. Set to `bytes32(0)` for immediate L2-transaction entries executed inline by `postAndVerifyBatch` or via `executeL2Txs`. Non-zero for entries triggered by a proxy call. |
| `l2ToL1Calls` | `L2ToL1Call[]` | The L2→L1 calls to execute, run in order. Reentrant frames (nested L1→L2 calls) carry their own sub-arrays rather than sharing this one — there is no global flat-call cursor or `callCount` partition. |
| `expectedL1ToL2Calls` | `ExpectedL1ToL2Call[]` | The unified reentrant table. Each row opens a reentrant frame when its key is matched during execution. |
| `rollingHash` | `bytes32` | The expected value of `_rollingHash` after all calls and nesting boundaries complete. Checked on-chain; any divergence from the pre-computed execution tree reverts `RollingHashMismatch`. |
| `destinationRollupId` | `uint64` | The rollup whose queue this entry is published into during `postAndVerifyBatch`'s deferred publish step. Must match the consumer's rollup and appear in the batch's `rollupIdsWithProofSystems[]`. |
| `success` | `bool` | Whether the top-level call returns (`true`) or reverts (`false`) with `returnData`. |
| `returnData` | `bytes` | The pre-computed return value delivered back to the caller of `executeCrossChainCall`, or the revert payload when `success == false`. |

### `StaticExecutionEntry` (L1)

The TOP-LEVEL counterpart to `ExecutionEntry` for read-only cross-chain calls: a call resolved via `staticCrossChainCall` **outside** any execution. Lives in the batch's transient static pool while a batch is mid-flight, otherwise in the calling rollup's persistent `staticEntryQueue`. Reverting top-level reads land here (`success == false`); state-changing top-level calls are `ExecutionEntry`s instead. Field order mirrors `ExecutionEntry`; there is no reentrant table, since a reentrant read re-enters the pool as another `StaticExecutionEntry`.

```solidity
struct StaticExecutionEntry {
    ExpectedStateRootPerRollup[] expectedStateRoots;
    bytes32                     proxyEntryHash;
    L2ToL1Call[]                l2ToL1Calls;
    bytes32                     rollingHash;
    uint64                      destinationRollupId;
    bool                        success;
    bytes                       returnData;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `expectedStateRoots` | `ExpectedStateRootPerRollup[]` | State-root pins — part of the match predicate (full scan). A candidate only matches when every pin equals the live `rollups[rollupId].stateRoot`; a non-matching pin skips the candidate rather than reverting on it. Since there is no block gate on the static path, these pins are what bounds freshness — as long as they match the live roots, the entry resolves regardless of how many blocks have passed. `destinationRollupId` must itself be one of the pins (`StaticEntryDestinationNotPinned`), so the set can never be empty. |
| `proxyEntryHash` | `bytes32` | The inbound call's `crossChainCallHash` (with `isStatic = true` folded in). Mirrors `ExecutionEntry.proxyEntryHash`. |
| `l2ToL1Calls` | `L2ToL1Call[]` | Read-only sub-calls, run via STATICCALL during resolution, in order. No reentrant frames. |
| `rollingHash` | `bytes32` | The expected untagged rolling hash of the sub-calls (`keccak256(prev, success, retData)` per sub-call, seeded at `bytes32(0)`). An empty `l2ToL1Calls[]` must carry a hash of `0`. |
| `destinationRollupId` | `uint64` | The rollup whose static pool this entry routes to. Must match the calling proxy's rollup; re-checked at match time. |
| `success` | `bool` | Whether resolution returns (`true`) or reverts (`false`) with `returnData`. |
| `returnData` | `bytes` | The pre-computed return value, or the revert payload when `success == false`. |

---

### `ExpectedStateRootPerRollup`

A rollup's expected state root, used both as an optional composer-supplied assertion on `postAndVerifyBatch` (`ProofSystemBatchPerVerificationEntries.expectedStateRootPerRollup[]`) and as the match-time pin set on `StaticExecutionEntry.expectedStateRoots[]`. A candidate matches when every pin equals the live `rollups[rollupId].stateRoot`.

```solidity
struct ExpectedStateRootPerRollup {
    uint64  rollupId;
    bytes32 stateRoot;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `rollupId` | `uint64` | The rollup whose state root is pinned or asserted. |
| `stateRoot` | `bytes32` | The expected value of `rollups[rollupId].stateRoot`. As a composer assertion on `postAndVerifyBatch`, any mismatch reverts `ExpectedStateRootMismatch`. As a `StaticExecutionEntry` pin, a mismatch simply skips that candidate rather than reverting. |

### `ProofSystemBatchPerVerificationEntries`

The single argument passed to `EEZ.postAndVerifyBatch`. Contains one batch's complete payload: optional state-root assertions, execution entries, static entries, proof systems with their per-rollup assignments, blob indices, calldata, proofs, and a block number binding.

```solidity
struct ProofSystemBatchPerVerificationEntries {
    ExpectedStateRootPerRollup[] expectedStateRootPerRollup;
    ExecutionEntry[]             entries;
    StaticExecutionEntry[]       staticEntries;
    uint256                      immediateEntryCount;
    uint256                      immediateStaticEntryCount;
    address[]                    proofSystems;
    RollupIdWithProofSystems[]   rollupIdsWithProofSystems;
    uint256[]                    blobIndices;
    bytes                        callData;
    bytes[]                      proofs;
    uint64                       blockNumber;
    bool                         bindMsgSenderInPublicInput;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `expectedStateRootPerRollup` | `ExpectedStateRootPerRollup[]` | Optional composer-supplied state-root assertions, checked against the live `rollups[rollupId].stateRoot` before anything else runs. Any mismatch reverts `ExpectedStateRootMismatch`. Distinct from the per-entry pins on `StaticExecutionEntry` — this is a batch-level guard the composer can use to fail fast. |
| `entries` | `ExecutionEntry[]` | All execution entries in this batch. The first `immediateEntryCount` entries are executed immediately in this call (leading L2-transaction and meta-hook entries); the remainder are saved in storage and published to per-rollup queues. |
| `staticEntries` | `StaticExecutionEntry[]` | All top-level static entries in this batch. The first `immediateStaticEntryCount` load into the transient static pool for the meta-hook window; the remainder publish to per-rollup `staticEntryQueue`s. |
| `immediateEntryCount` | `uint256` | Number of leading `entries` executed this transaction (immediate L2 transactions plus meta-hook/account-abstraction entries), rather than queued. An UNPROVEN dispatch parameter — not folded into the public input, so the immediate/persistent split can be re-tuned without re-proving. |
| `immediateStaticEntryCount` | `uint256` | Number of leading `staticEntries` loaded into the transient static pool. Also UNPROVEN. Must be `<= staticEntries.length`, and a non-zero count requires a non-zero `immediateEntryCount` — the transient static pool is only reachable while transient entries are mid-flight. |
| `proofSystems` | `address[]` | The batch-global list of proof system addresses, sorted strictly ascending. No duplicates and no `address(0)`. Each proof system in this array must supply one proof in `proofs[]`. |
| `rollupIdsWithProofSystems` | `RollupIdWithProofSystems[]` | Maps each participating rollup to its chosen subset of `proofSystems[]`. Must be sorted strictly ascending by `rollupId`. Each rollup's `proofSystemIndexes[]` must be strictly ascending indices into `proofSystems[]`. |
| `blobIndices` | `uint256[]` | Indices into the transaction's EIP-4844 blob list that this batch consumes. These blob hashes are folded into the shared public input. |
| `callData` | `bytes` | Batch-scoped calldata. Its `keccak256` hash is folded into the shared public input. |
| `proofs` | `bytes[]` | One proof per proof system in `proofSystems[]` (parallel arrays). Each proof is passed to `IProofSystem(proofSystems[k]).verify(proofs[k], publicInputsHash[k])`. |
| `blockNumber` | `uint64` | The single L1 block the batch binds to. Forwarded to each rollup's [`IRollupContract.getCustomData(blockNumber)`](/contracts/interfaces/irollupcontract). Pass `0` for no block context; pass `type(uint64).max` for latest context. |
| `bindMsgSenderInPublicInput` | `bool` | When `true`, folds `msg.sender` into the public input so only the address the proof committed to can land the batch (front-run protection). When `false`, folds `address(0)`, so anyone may submit. |

### `RollupIdWithProofSystems`

Pairs a rollup ID with the subset of the batch's `proofSystems[]` that this rollup accepts. Used inside `ProofSystemBatchPerVerificationEntries.rollupIdsWithProofSystems[]`.

```solidity
struct RollupIdWithProofSystems {
    uint64   rollupId;
    uint64[] proofSystemIndexes;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `rollupId` | `uint64` | A registered rollup ID participating in this batch. |
| `proofSystemIndexes` | `uint64[]` | Strictly-increasing indices into the batch's global `proofSystems[]` array selecting the proof systems this rollup accepts. The length must satisfy this rollup's threshold as enforced by its [`IRollupContract.checkProofSystemsAndGetVkeys`](/contracts/interfaces/irollupcontract). |

### `ProxyInfo`

Records the identity of a registered `CrossChainProxy` in the `authorizedProxies` mapping. Direction-neutral — used by both L1 (`EEZ`) and L2 (`EEZL2`) managers.

```solidity
struct ProxyInfo {
    bool    isProxy;
    address originalAddress;
    uint64  originalRollupId;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `isProxy` | `bool` | Existence flag, set on registration. Callers check this before trusting the rest of the struct — an unregistered address reads as all-zero fields otherwise, which would be indistinguishable from a real proxy pointed at rollup `0`. |
| `originalAddress` | `address` | The address of the contract on the remote chain that this proxy represents. |
| `originalRollupId` | `uint64` | The rollup ID of the chain where `originalAddress` lives. |

### `RollupConfig`

Per-rollup configuration held by the central EEZ registry. Ownership, threshold, and vkeys live on the separate `IRollupContract` manager; the registry holds only execution state.

```solidity
struct RollupConfig {
    address rollupContract;
    bytes32 stateRoot;
    uint256 etherBalance;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `rollupContract` | `address` | The address of the `IRollupContract`-conforming manager for this rollup. Immutable after registration — there is no `setRollupContract` function. |
| `stateRoot` | `bytes32` | The current committed state root for this rollup. Updated by `_applyStateUpdates` (during `executeCrossChainCall` / `executeL2Txs`) and by `setStateRoot` (owner escape hatch via the manager). |
| `etherBalance` | `uint256` | ETH held by the registry on behalf of this rollup. Adjusted by `etherDelta` in each `StateUpdate`. |

### `RollupVerification`

Per-rollup deferred-consumption record (`verificationByRollup[rollupId]`), populated by `postAndVerifyBatch`: the batch's entries awaiting consumption, a cursor tracking how far each queue has been consumed, and the block the rollup was last verified in.

```solidity
struct RollupVerification {
    uint64                 lastVerifiedBlock;
    uint64                 entryQueueIndex;
    ExecutionEntry[]       entryQueue;
    StaticExecutionEntry[] staticEntryQueue;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `lastVerifiedBlock` | `uint64` | The block number of the most recent `postAndVerifyBatch` call that touched this rollup. Serves three roles: (a) a per-block reset marker — any batch touching this rollup first wipes `entryQueue` / `staticEntryQueue` and resets `entryQueueIndex`, so a same-block re-verify replaces rather than appends to the prior batch's entries; (b) a read gate for entry consumers (`executeCrossChainCall` and `executeL2Txs` require `lastVerifiedBlock == block.number` before reading); and (c) the lockout check for the owner-escape path `setStateRoot`, which reverts `RollupBatchActiveThisBlock` when it equals the current block. Note this gate does **not** apply to the static-read path — `staticCrossChainCall` has no block gate; freshness there is governed entirely by `staticEntryQueue`'s `expectedStateRoots` pins. |
| `entryQueueIndex` | `uint64` | Cursor into `entryQueue`, advanced as entries are consumed. Reset to `0` whenever the queue is wiped on a same-block re-verify. |
| `entryQueue` | `ExecutionEntry[]` | The persistent, per-rollup queue of execution entries published by `postAndVerifyBatch`. Consumed in order via `entryQueueIndex`. |
| `staticEntryQueue` | `StaticExecutionEntry[]` | The persistent, per-rollup queue of top-level static entries published by `postAndVerifyBatch`. Scanned by `staticCrossChainCall` outside any execution. |

## L2 Types (`IEEZL2.sol`)

### `CrossChainCall`

A single call in an L2 execution entry's flat call array (`incomingCalls[]`), or in a reentrant/static frame's own sub-array. Field-for-field identical to L1's `L2ToL1Call` — only the type name differs.

```solidity
struct CrossChainCall {
    uint16  revertNextNCalls;
    bool    isStatic;
    uint64  gas;
    address sourceAddress;
    uint64  sourceRollupId;
    address targetAddress;
    uint256 value;
    bytes   data;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `revertNextNCalls` | `uint16` | When non-zero, force-reverts this call and the next `revertNextNCalls - 1` calls (this one included). The rolling hash still records real call outcomes; only EVM state changes are rolled back. `0` means no forced revert. |
| `isStatic` | `bool` | When `true`, dispatched via STATICCALL. Must have `value == 0`. |
| `gas` | `uint64` | Gas limit for the target call. `0` means forward all remaining gas. |
| `sourceAddress` | `address` | The caller identity on the source chain. Used with `sourceRollupId` to derive the `CrossChainProxy` through which the call is forwarded. |
| `sourceRollupId` | `uint64` | The rollup ID of the source chain. Pass `0` for calls from L1 (mainnet). |
| `targetAddress` | `address` | The contract to call on this L2. |
| `value` | `uint256` | ETH to forward. When the call succeeds and `value > 0`, the ETH is drawn from the manager's balance (funded by `msg.value` on `executeIncomingCrossChainCall`). |
| `data` | `bytes` | Calldata for the target. |

---

### `ExpectedOutgoingCrossChainCall`

One row of the unified reentrant table for a cross-chain call fired from this L2 toward a remote rollup during execution. Field-for-field equivalent to L1's `ExpectedL1ToL2Call`, with self-relative naming (`expectedOutgoingHash`, `incomingCalls`) and no `destinationRollupId` (L2 has a single rollup and does not need per-rollup routing for outgoing calls). Consumed sequentially from `ExecutionEntry.expectedOutgoingCalls[]`, forward-scanned by the `_lastOutgoingCallConsumed` cursor.

```solidity
struct ExpectedOutgoingCrossChainCall {
    bytes32          expectedOutgoingHash;
    CrossChainCall[] incomingCalls;
    bytes32          revertedOrStaticRollingHash;
    bool             success;
    bytes            returnData;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `expectedOutgoingHash` | `bytes32` | The position key: `keccak256(crossChainCallHash, expectedRollingHash)`. Uniquely pins the execution point the same way `expectedL1toL2Hash` does on L1. |
| `incomingCalls` | `CrossChainCall[]` | This frame's own sub-calls, run to completion. Every kind carries its own array — no shared partition with the parent entry. |
| `revertedOrStaticRollingHash` | `bytes32` | The expected rolling hash of the frame's sub-calls. Checked only for STATIC and REVERTED kinds. An empty `incomingCalls[]` must carry a hash of `bytes32(0)`. |
| `success` | `bool` | Whether the reentrant call returns (`true`) or reverts (`false`) with `returnData`. |
| `returnData` | `bytes` | The pre-computed return value delivered back to the caller, or the revert payload when `success == false`. |

---

### `ExecutionEntry` (L2)

The central TOP-LEVEL execution unit on L2. Leaner than the L1 version: no `stateUpdates`, no `destinationRollupId` — L2 has a single rollup, so neither is needed. Loaded by `loadExecutionTable` or `executeIncomingCrossChainCall`. `proxyEntryHash` is never `bytes32(0)` on L2 — there is no immediate-entry consumption path on the L2 side (`executeL2Txs` is L1-only).

```solidity
struct ExecutionEntry {
    bytes32                          proxyEntryHash;
    CrossChainCall[]                 incomingCalls;
    ExpectedOutgoingCrossChainCall[] expectedOutgoingCalls;
    bytes32                          rollingHash;
    bool                             success;
    bytes                            returnData;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `proxyEntryHash` | `bytes32` | The inbound proxy-entry call hash (`crossChainCallHash`) that triggers this entry. Must be non-zero on L2. Matched against the hash computed from the proxy's identity and live call context (or, in `executeIncomingCrossChainCall`, recomputed from the explicit parameters). |
| `incomingCalls` | `CrossChainCall[]` | The full flat list of calls this entry executes, in execution order. Reentrant frames carry their own sub-arrays rather than sharing this one. |
| `expectedOutgoingCalls` | `ExpectedOutgoingCrossChainCall[]` | The unified reentrant table for calls fired from this L2. Each row opens a reentrant frame when matched. |
| `rollingHash` | `bytes32` | The expected `_rollingHash` after all calls complete. Checked on-chain to verify the entire execution tree. |
| `success` | `bool` | Whether the top-level call returns (`true`) or reverts (`false`) with `returnData`. |
| `returnData` | `bytes` | The pre-computed return value delivered back to the caller of `executeCrossChainCall`, or returned by `executeIncomingCrossChainCall`; the revert payload when `success == false`. |

---

### `StaticExecutionEntry` (L2)

The TOP-LEVEL counterpart to `ExecutionEntry` for read-only cross-chain calls on L2, resolved via `staticCrossChainCall` outside any execution, from the `staticEntries` pool. Reverting top-level reads land here; state-changing top-level calls are `ExecutionEntry`s. Leaner than L1's version: no `expectedStateRoots` and no `destinationRollupId` — L2 has a single rollup and no state roots to pin against. Freshness instead comes from a block gate: the pool is only resolvable in the same block it was loaded (`lastLoadBlock == block.number`).

```solidity
struct StaticExecutionEntry {
    bytes32          proxyEntryHash;
    CrossChainCall[] incomingCalls;
    bytes32          rollingHash;
    bool             success;
    bytes            returnData;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `proxyEntryHash` | `bytes32` | The inbound call's `crossChainCallHash` (with `isStatic = true` folded in). Mirrors `ExecutionEntry.proxyEntryHash`, and is the sole match key on L2 (unlike L1, which also checks `destinationRollupId` and state-root pins). |
| `incomingCalls` | `CrossChainCall[]` | Read-only sub-calls, run via STATICCALL during resolution, in order. No reentrant frames — referenced proxies must already be deployed, since CREATE2 is unavailable inside a STATICCALL frame. |
| `rollingHash` | `bytes32` | The expected untagged rolling hash of the sub-calls (`keccak256(prev, success, retData)` per sub-call). An empty `incomingCalls[]` must carry a hash of `0`. |
| `success` | `bool` | Whether resolution returns (`true`) or reverts (`false`) with `returnData`. |
| `returnData` | `bytes` | The pre-computed return value, or the revert payload when `success == false`. |
