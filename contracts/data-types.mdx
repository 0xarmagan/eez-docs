EEZ uses two parallel families of execution structs: one for L1 (`IEEZ.sol`) and one for L2 (`IEEZL2.sol`). The L1 family uses absolute directional names (`L2ToL1Call`, `ExpectedL1ToL2Call`) because L1 always knows which direction a call moves. The L2 family uses self-relative names (`CrossChainCall` / `incomingCalls`, `ExpectedOutgoingCrossChainCall` / `expectedOutgoingCalls`) because an L2's cross-chain counterparty may be L1 or another L2 — absolute names would be wrong in the latter case. The L2 structs are intentionally leaner: they omit `StateDelta`, `destinationRollupId`, and `ExpectedStateRootPerRollup`, which are meaningful only in the context of L1's multi-rollup registry.

---

## L1 Types (`IEEZ.sol`)

### `StateDelta`

Describes one rollup's state transition caused by executing one entry. The `currentState` field is checked on-chain at consumption time against `rollups[rollupId].stateRoot`; a mismatch reverts `StateRootMismatch`. This makes entries content-addressed against the trajectory the proof committed to, preventing a stale or reordered entry from silently applying to the wrong chain state.

```solidity
struct StateDelta {
    uint256 rollupId;
    bytes32 currentState;
    bytes32 newState;
    int256  etherDelta;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `rollupId` | `uint256` | The rollup whose state transitions. Must be a registered rollup ID in the EEZ registry. |
| `currentState` | `bytes32` | The expected state root of `rollupId` immediately before this entry is applied. Checked at consumption time against `rollups[rollupId].stateRoot`; reverts `StateRootMismatch` on mismatch. |
| `newState` | `bytes32` | The state root to write into `rollups[rollupId].stateRoot` after the entry is applied. |
| `etherDelta` | `int256` | Signed change in the rollup's ETH balance held by the registry. Positive means the rollup gains ETH (deposit or bridged-in); negative means it loses ETH (withdrawal or bridged-out). The registry enforces `InsufficientRollupBalance` on negative deltas that would underflow. |

### `L2ToL1Call`

A single call in an L1 execution entry's flat call array (`l2ToL1Calls[]`). The array contains all calls for the entire entry in execution order — both entry-level calls and calls consumed by reentrant frames share the same flat array and the same `_currentL2ToL1Call` cursor. On L2, the structurally identical type is named `CrossChainCall`.

```solidity
struct L2ToL1Call {
    bool    isStatic;
    address targetAddress;
    uint256 value;
    bytes   data;
    address sourceAddress;
    uint256 sourceRollupId;
    uint256 revertSpan;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `isStatic` | `bool` | When `true`, the call is dispatched via STATICCALL — read-only, carries no ETH, and reverts on any state write. A static call with a non-zero `value` field is rejected with `StaticCallWithValue`. |
| `targetAddress` | `address` | The contract to call on the destination rollup (L1 in this context). |
| `value` | `uint256` | ETH to forward with the call, in wei. Only accrues toward the entry's ether accounting when the call succeeds. Must be zero for static calls. |
| `data` | `bytes` | The calldata — ABI-encoded function selector and arguments. |
| `sourceAddress` | `address` | The identity of the caller on the source rollup. Together with `sourceRollupId`, this is used to derive (or auto-create) the `CrossChainProxy` through which the call is forwarded. |
| `sourceRollupId` | `uint256` | The rollup ID of the chain where the call originated. Pass `0` for calls originating from L1 (mainnet) itself. |
| `revertSpan` | `uint256` | When non-zero, wraps this call and the next `revertSpan - 1` calls in a forced-revert context. The calls execute (and may succeed), but all EVM state changes are rolled back. The rolling hash still records the calls' real outcomes. Use this when the source chain's prover marks a sequence as reverted even though the destination calls themselves succeed. Set to `0` for normal calls. |

### `ExpectedL1ToL2Call`

Pre-computed result for a **successful** reentrant cross-chain call back from L1 to an L2, triggered mid-execution. Consumed sequentially from the entry's `expectedL1ToL2Calls` array when a destination contract calls back into the manager via a registered proxy. On L2, the structurally identical type is named `ExpectedOutgoingCrossChainCall`.

```solidity
struct ExpectedL1ToL2Call {
    bytes32 crossChainCallHash;
    uint256 destinationRollupId;
    uint256 callCount;
    bytes   returnData;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `crossChainCallHash` | `bytes32` | The hash of the reentrant call — computed with `computeCrossChainCallHash`. The manager matches this field against the hash recomputed from the proxy's identity and the live call context; a mismatch means the entry was built for a different reentrant call. |
| `destinationRollupId` | `uint256` | The rollup this reentrant call targets. Must be one of the rollups whose state deltas are carried by the host entry. At consumption, the manager verifies this equals the calling proxy's registered rollup ID (`proxyInfo.originalRollupId`). |
| `callCount` | `uint256` | The number of calls the reentrant frame consumes from the parent entry's flat `l2ToL1Calls[]` array. The same global `_currentL2ToL1Call` cursor advances through these calls inside the reentrant frame; the outer frame resumes from where the cursor left off when the reentrant frame returns. |
| `returnData` | `bytes` | The pre-computed return value delivered back to the caller in the destination contract. The caller sees this as the return value of its cross-chain proxy call. |

### `ExpectedLookup` (L1)

A nested lookup: the pre-computed result of a reentrant cross-chain call that is looked up rather than executed as a normal call. Lives inside `ExecutionEntry.expectedLookups[]` — it is scoped to its parent entry and has no queue routing. Matched by the four-tuple `(crossChainCallHash, l2ToL1CallNumber, lastL1ToL2CallConsumed, executingLookupIndex)`.

Use this struct for two situations inside an entry: a reentrant STATICCALL (static mode, `failed == false`) and a reentrant call that must revert — one the destination catches with `try/catch` (reverted mode, `failed == true`).

```solidity
struct ExpectedLookup {
    bytes32              crossChainCallHash;
    uint256              destinationRollupId;
    bytes                returnData;
    bool                 failed;
    uint64               l2ToL1CallNumber;
    uint64               lastL1ToL2CallConsumed;
    uint64               executingLookupIndex;
    L2ToL1Call[]         l2ToL1Calls;
    ExpectedL1ToL2Call[] expectedL1ToL2Calls;
    uint256              callCount;
    bytes32              rollingHash;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `crossChainCallHash` | `bytes32` | Hash of the looked-up call. For static lookups, computed with `value = 0`. |
| `destinationRollupId` | `uint256` | The rollup this looked-up call targets. Must match the calling proxy's rollup. Also serves as part of the match predicate: [`postAndVerifyBatch`](/contracts/eez) verifies it is pinned by the host entry's state deltas. |
| `returnData` | `bytes` | The pre-computed result. Returned to the caller in static mode (`failed == false`). Used as the revert payload in reverted mode (`failed == true`). |
| `failed` | `bool` | When `true`, the lookup executes any sub-calls as a mini-entry and then reverts with `returnData`. The caller's `try/catch` block catches the revert. When `false`, the lookup runs sub-calls as STATICCALLs and returns `returnData` on success. |
| `l2ToL1CallNumber` | `uint64` | The value of `_currentL2ToL1Call` at the moment this lookup was observed during simulation. Part of the four-tuple match key. |
| `lastL1ToL2CallConsumed` | `uint64` | The value of `_lastL1ToL2CallConsumed` at observation time. Part of the four-tuple match key. |
| `executingLookupIndex` | `uint64` | The execution context at observation: `0` if fired at the host entry level, `k` if fired inside the sub-execution of `expectedLookups[k-1]` of the same host. Enforced on-chain; keeps the flat host table unambiguous across execution contexts. |
| `l2ToL1Calls` | `L2ToL1Call[]` | Sub-calls executed at resolution. In static mode, run as STATICCALLs via `_processNStaticCalls` (no revertSpan support). In reverted mode, run as real calls partitioned by `callCount` against `expectedL1ToL2Calls`. Empty when no sub-calls are needed. |
| `expectedL1ToL2Calls` | `ExpectedL1ToL2Call[]` | Reentrant table for reverted-mode sub-execution. Empty for static mode. |
| `callCount` | `uint256` | Number of entry-level iterations in reverted-mode sub-execution. Zero for static mode. |
| `rollingHash` | `bytes32` | Expected hash of the sub-call results. Uses the untagged schema in static mode and the tagged entry schema in reverted mode. An empty `l2ToL1Calls[]` must carry `rollingHash == bytes32(0)`. |

### `ExecutionEntry` (L1)

The central execution unit on L1. Each entry carries one rollup's state transition plus a flat list of all calls to execute, a parallel reentrant-call table, entry-scoped nested lookups, and integrity metadata. Loaded by `postAndVerifyBatch` and routed into per-rollup queues.

```solidity
struct ExecutionEntry {
    StateDelta[]         stateDeltas;
    bytes32              proxyEntryHash;
    uint256              destinationRollupId;
    bytes                returnData;
    L2ToL1Call[]         l2ToL1Calls;
    ExpectedL1ToL2Call[] expectedL1ToL2Calls;
    ExpectedLookup[]     expectedLookups;
    uint256              callCount;
    bytes32              rollingHash;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `stateDeltas` | `StateDelta[]` | All state transitions caused by executing this entry. At least one delta must be present (the prover asserts this — not enforced on-chain). Each delta's `currentState` is checked against the live registry state at consumption time. |
| `proxyEntryHash` | `bytes32` | The cross-chain call hash that triggers this entry. Set to `bytes32(0)` for immediate (L2TX-style) entries that are executed inline by `postAndVerifyBatch` or via `executeL2TX`. Non-zero for entries triggered by a proxy call. |
| `destinationRollupId` | `uint256` | The rollup whose queue this entry is published into during `postAndVerifyBatch`'s deferred publish step. Must appear in the batch's `rollupIdsWithProofSystems[]`. |
| `returnData` | `bytes` | The pre-computed return value delivered back to the caller of `executeCrossChainCall`. All top-level entries succeed; reverting top-level results are expressed as `LookupCall` entries with `failed == true`, not as entries with a failed `returnData`. |
| `l2ToL1Calls` | `L2ToL1Call[]` | The full flat list of every call this entry executes, in execution order. Partitioned between the entry's top-level frame and any reentrant frames by `callCount` and `expectedL1ToL2Calls[i].callCount`. The invariant: `callCount + Σ expectedL1ToL2Calls[i].callCount == l2ToL1Calls.length`. |
| `expectedL1ToL2Calls` | `ExpectedL1ToL2Call[]` | Pre-computed results for successful reentrant calls. Consumed sequentially — index `i` is consumed by the `i`-th reentrant call that fires during execution. |
| `expectedLookups` | `ExpectedLookup[]` | Entry-scoped nested lookups for reentrant STATICCALLs and try/catch'd reverting reentrant calls. Matched by the four-tuple at lookup time. |
| `callCount` | `uint256` | Number of calls the entry's top-level `_processNCalls` frame processes from `l2ToL1Calls[]`. Does not include calls consumed inside reentrant frames. |
| `rollingHash` | `bytes32` | The expected value of `_rollingHash` after all calls and nesting boundaries complete. Checked on-chain; any divergence from the pre-computed execution tree reverts `RollingHashMismatch`. |

### `LookupCall` (L1)

A top-level lookup: the pre-computed result for a call resolved outside an active execution — a top-level static read via `staticCallLookup` or a top-level reverting call executed via `_tryRevertedTopLevelLookup`. Lives in the persistent per-rollup `lookupQueue` or in the transient `_transientLookupCalls` pool. Consumable only when `_insideExecution() == false`.

```solidity
struct LookupCall {
    bytes32                      crossChainCallHash;
    uint256                      destinationRollupId;
    bytes                        returnData;
    bool                         failed;
    L2ToL1Call[]                 l2ToL1Calls;
    ExpectedL1ToL2Call[]         expectedL1ToL2Calls;
    ExpectedLookup[]             expectedLookups;
    uint256                      callCount;
    bytes32                      rollingHash;
    ExpectedStateRootPerRollup[] expectedStateRoots;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `crossChainCallHash` | `bytes32` | Hash of the looked-up call. Part of the match key. |
| `destinationRollupId` | `uint256` | The rollup this lookup is published under and the rollup whose proxy must trigger the resolution. For persistent lookups, this controls which `lookupQueue` the entry lands in. |
| `returnData` | `bytes` | The pre-computed result. Returned on success; used as the revert payload when `failed == true`. |
| `failed` | `bool` | When `true`, executing this lookup runs any sub-execution and reverts with `returnData`. When `false`, runs sub-calls as STATICCALLs and returns `returnData`. |
| `l2ToL1Calls` | `L2ToL1Call[]` | Sub-calls to execute at resolution time. Static mode: STATICCALL, no `revertSpan`. Reverted mode: real calls partitioned by `callCount`. |
| `expectedL1ToL2Calls` | `ExpectedL1ToL2Call[]` | Reentrant table for reverted-mode sub-execution. Empty for static mode. |
| `expectedLookups` | `ExpectedLookup[]` | Nested lookups for the reverted-mode sub-execution. These resolve from this lookup's own table (Solidity forbids recursive structs, so deeper reverted-lookup executions all share this flat table). Empty for static mode. |
| `callCount` | `uint256` | Top-level iterations in reverted-mode sub-execution. Zero for static mode. |
| `rollingHash` | `bytes32` | Expected hash of sub-call results. Untagged schema for static mode; tagged entry schema for reverted mode. |
| `expectedStateRoots` | `ExpectedStateRootPerRollup[]` | State-root pins — part of the match predicate. A lookup candidate only matches when every pin equals the live `rollups[rollupId].stateRoot`. A non-matching pin skips the candidate (full-scan semantics — the lookup is not reverted on, just passed over). This binds the lookup to a specific point on each relevant rollup's state trajectory. |

---

### `ExpectedStateRootPerRollup`

A state-root pin used inside `LookupCall.expectedStateRoots` on L1. Binds a top-level lookup to a specific point on a rollup's state trajectory. The match check is full-scan: if any pin fails to match the live state root, the lookup candidate is skipped rather than reverted on.

```solidity
struct ExpectedStateRootPerRollup {
    uint256 rollupId;
    bytes32 stateRoot;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `rollupId` | `uint256` | The rollup whose state root is pinned. |
| `stateRoot` | `bytes32` | The expected value of `rollups[rollupId].stateRoot` at the moment this lookup is resolved. If the live state root differs, this lookup candidate is skipped. |

### `ProofSystemBatchPerVerificationEntries`

The single argument passed to `EEZ.postAndVerifyBatch`. Contains one batch's complete payload: execution entries, lookup calls, proof systems with their per-rollup assignments, blob indices, calldata, proofs, and a block number binding.

```solidity
struct ProofSystemBatchPerVerificationEntries {
    ExecutionEntry[]              entries;
    LookupCall[]                  l1ToL2lookupCalls;
    uint256                       transientExecutionEntryCount;
    uint256                       transientLookupCallCount;
    address[]                     proofSystems;
    RollupIdWithProofSystems[]    rollupIdsWithProofSystems;
    uint256[]                     blobIndices;
    bytes                         callData;
    bytes[]                       proofs;
    uint64                        blockNumber;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `entries` | `ExecutionEntry[]` | All execution entries in this batch. The first `transientExecutionEntryCount` entries go into the transient table; the rest are published to per-rollup queues. |
| `l1ToL2lookupCalls` | `LookupCall[]` | All top-level lookup calls in this batch. The first `transientLookupCallCount` go into the transient lookup table; the rest go to per-rollup `lookupQueue`s. Nested lookups live inside their entries' `expectedLookups` and are not listed here. |
| `transientExecutionEntryCount` | `uint256` | Number of entries from the front of `entries[]` to load into the transient table. Must be `<= entries.length`. These entries are available for immediate consumption in the same transaction via `executeCrossChainCall` or the meta hook. |
| `transientLookupCallCount` | `uint256` | Number of lookup calls from the front of `l1ToL2lookupCalls[]` to load into the transient table. Must be `<= l1ToL2lookupCalls.length`. |
| `proofSystems` | `address[]` | The batch-global list of proof system addresses, sorted strictly ascending. No duplicates and no `address(0)`. Each proof system in this array must supply one proof in `proofs[]`. |
| `rollupIdsWithProofSystems` | `RollupIdWithProofSystems[]` | Maps each participating rollup to its chosen subset of `proofSystems[]`. Must be sorted strictly ascending by `rollupId`. Each rollup's `proofSystemIndex[]` must be strictly ascending indices into `proofSystems[]`. |
| `blobIndices` | `uint256[]` | Indices into the transaction's EIP-4844 blob list that this batch consumes. These blob hashes are folded into `sharedPublicInput`. |
| `callData` | `bytes` | Batch-scoped calldata. Its `keccak256` hash is folded into `sharedPublicInput`. |
| `proofs` | `bytes[]` | One proof per proof system in `proofSystems[]` (parallel arrays). Each proof is passed to `IProofSystem(proofSystems[k]).verify(proofs[k], publicInputsHash[k])`. |
| `blockNumber` | `uint64` | The single L1 block the batch binds to. Forwarded to each rollup's [`IRollupContract.getCustomData(blockNumber)`](/contracts/interfaces/irollupcontract). Pass `0` for no block context; pass `type(uint64).max` for latest context. |

### `RollupIdWithProofSystems`

Pairs a rollup ID with the subset of the batch's `proofSystems[]` that this rollup accepts. Used inside `ProofSystemBatchPerVerificationEntries.rollupIdsWithProofSystems[]`.

```solidity
struct RollupIdWithProofSystems {
    uint256  rollupId;
    uint64[] proofSystemIndex;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `rollupId` | `uint256` | A registered rollup ID participating in this batch. Must be greater than zero (zero is the mainnet sentinel, never a registered rollup ID). |
| `proofSystemIndex` | `uint64[]` | Strictly-increasing indices into the batch's global `proofSystems[]` array selecting the proof systems this rollup accepts. The length must satisfy this rollup's threshold as enforced by its [`IRollupContract.checkProofSystemsAndGetVkeys`](/contracts/interfaces/irollupcontract). |

### `ProxyInfo`

Records the identity of a registered `CrossChainProxy` in the `authorizedProxies` mapping. Direction-neutral — used by both L1 (`EEZ`) and L2 (`EEZL2`) managers.

```solidity
struct ProxyInfo {
    address originalAddress;
    uint64  originalRollupId;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `originalAddress` | `address` | The address of the contract on the remote chain that this proxy represents. |
| `originalRollupId` | `uint64` | The rollup ID of the chain where `originalAddress` lives. |

### `RollupConfig`

Per-rollup configuration held by the central EEZ registry. Ownership, threshold, and vkeys live on the separate `IRollupContract` manager; the registry holds only execution state.

```solidity
struct RollupConfig {
    address rollupContract;
    bytes32 stateRoot;
    uint256 etherBalance;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `rollupContract` | `address` | The address of the `IRollupContract`-conforming manager for this rollup. Immutable after registration — there is no `setRollupContract` function. |
| `stateRoot` | `bytes32` | The current committed state root for this rollup. Updated by `_applyStateDeltas` (during `executeCrossChainCall` / `executeL2TX`) and by `setStateRoot` (owner escape hatch via the manager). |
| `etherBalance` | `uint256` | ETH held by the registry on behalf of this rollup. Adjusted by `etherDelta` in each `StateDelta`. |

### `RollupVerification`

Per-rollup deferred-consumption queue plus a per-block reset marker. Held internally by the registry (`verificationByRollup[rollupId]`) and populated by `postAndVerifyBatch`. `lastVerifiedBlock` serves three roles: a per-block reset marker (any `postAndVerifyBatch` call touching this rollup wipes `executionQueue` / `lookupQueue` and resets the cursor, so a same-block re-verify replaces rather than appends to the prior batch's entries), a read gate for consumers (`executeCrossChainCall`, `executeL2TX`, and `staticCallLookup` all require `lastVerifiedBlock == block.number` before reading), and a lockout signal for the owner-escape path `EEZ.setStateRoot`, which reverts `RollupBatchActiveThisBlock` when it equals the current block.

```solidity
struct RollupVerification {
    uint256 lastVerifiedBlock;
    ExecutionEntry[] executionQueue;
    LookupCall[] lookupQueue;
    uint256 executionQueueIndex;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `lastVerifiedBlock` | `uint256` | The block number of the most recent `postAndVerifyBatch` call that touched this rollup. Doubles as a per-block reset marker, a read gate for consumers, and the lockout check for `setStateRoot`. |
| `executionQueue` | `ExecutionEntry[]` | The persistent, per-rollup queue of execution entries published by `postAndVerifyBatch`. Consumed in order via `executionQueueIndex`. |
| `lookupQueue` | `LookupCall[]` | The persistent, per-rollup queue of top-level lookup calls published by `postAndVerifyBatch`. Scanned by `staticCallLookup` and reverting top-level lookup consumption. |
| `executionQueueIndex` | `uint256` | Cursor into `executionQueue`, advanced as entries are consumed. Reset to `0` whenever the queue is wiped on a same-block re-verify. |

## L2 Types (`IEEZL2.sol`)

### `CrossChainCall`

A single call in an L2 execution entry's flat call array (`incomingCalls[]`). Field-for-field identical to L1's `L2ToL1Call` — only the type name differs. The array is shared between the entry's top-level frame and reentrant frames; both advance the same `_currentIncomingCall` cursor.

```solidity
struct CrossChainCall {
    bool    isStatic;
    address targetAddress;
    uint256 value;
    bytes   data;
    address sourceAddress;
    uint256 sourceRollupId;
    uint256 revertSpan;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `isStatic` | `bool` | When `true`, dispatched via STATICCALL. Must have `value == 0`. |
| `targetAddress` | `address` | The contract to call on this L2. |
| `value` | `uint256` | ETH to forward. When the call succeeds and `value > 0`, the ETH is drawn from the manager's balance (funded by `msg.value` on `executeIncomingCrossChainCall`). |
| `data` | `bytes` | Calldata for the target. |
| `sourceAddress` | `address` | The caller identity on the source chain. Used with `sourceRollupId` to derive the `CrossChainProxy` through which the call is forwarded. |
| `sourceRollupId` | `uint256` | The rollup ID of the source chain. Pass `0` for calls from L1 (mainnet). |
| `revertSpan` | `uint256` | When non-zero, wraps this and the next `revertSpan - 1` calls in a forced-revert context. The rolling hash still records real call outcomes; only EVM state changes are rolled back. |

---

### `ExpectedOutgoingCrossChainCall`

Pre-computed result for a **successful** reentrant cross-chain call fired from this L2 toward a remote rollup during execution. Field-for-field identical to L1's `ExpectedL1ToL2Call`, minus `destinationRollupId` (L2 has a single rollup and does not need per-rollup routing for outgoing calls). Consumed sequentially from `ExecutionEntry.expectedOutgoingCalls[]`.

```solidity
struct ExpectedOutgoingCrossChainCall {
    bytes32 crossChainCallHash;
    uint256 callCount;
    bytes   returnData;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `crossChainCallHash` | `bytes32` | Hash of the reentrant call. Matched against the hash recomputed from the proxy's identity and live call context. |
| `callCount` | `uint256` | Number of calls the reentrant frame consumes from the parent entry's flat `incomingCalls[]` array. The outer frame resumes after these calls complete. |
| `returnData` | `bytes` | The pre-computed return value delivered back to the caller. |

---

### `ExpectedLookup` (L2)

A nested lookup on L2 — structurally equivalent to the L1 `ExpectedLookup` but with self-relative field names and without `destinationRollupId`. Matched by the four-tuple `(crossChainCallHash, callNumber, lastOutgoingCallConsumed, executingLookupIndex)`.

```solidity
struct ExpectedLookup {
    bytes32                          crossChainCallHash;
    bytes                            returnData;
    bool                             failed;
    uint64                           callNumber;
    uint64                           lastOutgoingCallConsumed;
    uint64                           executingLookupIndex;
    CrossChainCall[]                 incomingCalls;
    ExpectedOutgoingCrossChainCall[] expectedOutgoingCalls;
    uint256                          callCount;
    bytes32                          rollingHash;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `crossChainCallHash` | `bytes32` | Hash of the looked-up call. For static lookups, computed with `value = 0`. |
| `returnData` | `bytes` | The pre-computed result. Returned on success; used as the revert payload when `failed == true`. |
| `failed` | `bool` | When `true`, the lookup executes sub-calls and reverts with `returnData`. When `false`, runs sub-calls as STATICCALLs and returns `returnData`. |
| `callNumber` | `uint64` | The value of `_currentIncomingCall` at observation time. Part of the four-tuple match key. |
| `lastOutgoingCallConsumed` | `uint64` | The value of `_lastOutgoingCallConsumed` at observation time. Part of the four-tuple match key. |
| `executingLookupIndex` | `uint64` | Execution context at observation: `0` at entry/host level; `k` inside the sub-execution of `expectedLookups[k-1]`. Enforced on-chain. |
| `incomingCalls` | `CrossChainCall[]` | Sub-calls executed at resolution. STATICCALL in static mode; real calls in reverted mode. |
| `expectedOutgoingCalls` | `ExpectedOutgoingCrossChainCall[]` | Reentrant table for reverted-mode sub-execution. Empty for static mode. |
| `callCount` | `uint256` | Top-level iterations in reverted-mode sub-execution. Zero for static mode. |
| `rollingHash` | `bytes32` | Expected hash of sub-call results. Untagged for static mode; tagged for reverted mode. |

---

### `ExecutionEntry` (L2)

The central execution unit on L2. Leaner than the L1 version: no `stateDeltas`, no `destinationRollupId`. Loaded by `loadExecutionTable` or `executeIncomingCrossChainCall`. `proxyEntryHash` is never `bytes32(0)` on L2 — there is no immediate-entry consumption path on the L2 side.

```solidity
struct ExecutionEntry {
    bytes32                          proxyEntryHash;
    CrossChainCall[]                 incomingCalls;
    ExpectedOutgoingCrossChainCall[] expectedOutgoingCalls;
    ExpectedLookup[]                 expectedLookups;
    uint256                          callCount;
    bytes                            returnData;
    bytes32                          rollingHash;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `proxyEntryHash` | `bytes32` | The cross-chain call hash that triggers this entry. Must be non-zero on L2. Matched against the hash computed from the proxy's identity and live call context (or, in `executeIncomingCrossChainCall`, recomputed from the explicit parameters). |
| `incomingCalls` | `CrossChainCall[]` | The full flat list of all calls this entry executes, in execution order. Shared between the top-level frame and any reentrant frames. |
| `expectedOutgoingCalls` | `ExpectedOutgoingCrossChainCall[]` | Pre-computed results for successful reentrant calls fired from this L2. Consumed sequentially. |
| `expectedLookups` | `ExpectedLookup[]` | Entry-scoped nested lookups for reentrant STATICCALLs and reverted reentrant calls. |
| `callCount` | `uint256` | Number of calls the entry's top-level frame processes. Together with `expectedOutgoingCalls[i].callCount`, partitions `incomingCalls[]` across the execution tree. |
| `returnData` | `bytes` | The pre-computed return value delivered back to the caller of `executeCrossChainCall` or returned by `executeIncomingCrossChainCall`. |
| `rollingHash` | `bytes32` | The expected `_rollingHash` after all calls complete. Checked on-chain to verify the entire execution tree. |

---

### `LookupCall` (L2)

A top-level lookup on L2 — equivalent to the L1 version but without `destinationRollupId` (single rollup) and without `expectedStateRoots` (L2 has no state roots to pin against). Matched by `crossChainCallHash` alone.

```solidity
struct LookupCall {
    bytes32                          crossChainCallHash;
    bytes                            returnData;
    bool                             failed;
    CrossChainCall[]                 incomingCalls;
    ExpectedOutgoingCrossChainCall[] expectedOutgoingCalls;
    ExpectedLookup[]                 expectedLookups;
    uint256                          callCount;
    bytes32                          rollingHash;
}
```

#### Fields

| Name | Type | Description |
| --- | --- | --- |
| `crossChainCallHash` | `bytes32` | Hash of the looked-up call. The sole match key on L2. |
| `returnData` | `bytes` | Pre-computed result. Returned on success; revert payload when `failed == true`. |
| `failed` | `bool` | When `true`, runs any sub-execution and reverts with `returnData`. When `false`, runs sub-calls as STATICCALLs and returns `returnData`. |
| `incomingCalls` | `CrossChainCall[]` | Sub-calls executed at resolution. STATICCALL in static mode; real calls in reverted mode. |
| `expectedOutgoingCalls` | `ExpectedOutgoingCrossChainCall[]` | Reentrant table for reverted-mode sub-execution. Empty for static mode. |
| `expectedLookups` | `ExpectedLookup[]` | Nested lookups for the reverted-mode sub-execution. Empty for static mode. |
| `callCount` | `uint256` | Top-level iterations in reverted-mode sub-execution. Zero for static mode. |
| `rollingHash` | `bytes32` | Expected hash of sub-call results. Untagged for static mode; tagged for reverted mode. |
